# Wiki 编译文件

Wiki 编译完成后自动在本目录保存 UTF-8 Markdown：

- `entities/<页面ID>.md`：具体实体，如药物、机构、人物、设备、产品。
- `concepts/<页面ID>.md`：抽象概念、疾病、机制、方法、原则。
- `syntheses/<页面ID>.md`：结合实体、概念形成的来源综合分析。
- `.history/<页面ID>/<版本ID>.md`：历史版本。
- `index.md`：系统维护的页面目录，包含草稿、发布和失效状态。
- `log.md`：按事件 ID 幂等追加的编译、发布和失效操作日志。

预编译依次生成实体页、概念页和综合分析页。模型提取知识点时明确实体/概念类别，编写页面时必须在 frontmatter 中输出正确的 `category: ENTITY|CONCEPT|SYNTHESIS`。资料未涉及具体实体时，实体文件夹可以为空，不会为了填满目录而生成知识。

页面文件使用稳定 ID 命名，`[[页面ID]]` 链接可跨文件夹对应同名文件。文件内容保留模型生成的完整 Markdown；审核状态、引用、标签和双向链接索引仍保存在数据库中。分类目录包含草稿和已失效版本，正式问答只使用数据库中有效的已发布版本。

旧版 SOURCE 来源页映射到 syntheses，TOPIC 主题页映射到 concepts；重新编译后采用模型识别的新类别。同步成功后会移除对应页面旧的平铺文件，保留所有历史版本。

不要直接修改系统生成的页面，后续同步会以数据库中的版本覆盖。已有编译结果会在文档 MCP 启动后自动补齐，不消耗模型 Token；文件写入失败会保留待同步任务并自动重试。

配置位于文档 MCP 的 `application.yml`：`doc-mcp.wiki.output-dir: ./docs/wiki`。开发环境从项目根目录或文档模块启动，均写入后端项目的本目录；容器内默认写入 `/app/docs/wiki`，Compose 已将其挂载至宿主机本目录。
