# 天医——循证医疗信息与安全支持智能体前端

基于 Vue 3 + Vite 的单页面应用，面向医疗信息解释、危险信号识别、循证检索和临床安全复核。系统只提供信息与沟通支持，不能替代医生诊断、药师审方或急救服务。

## 页面

- `/medical`：流式医疗信息问答、RAG、工具增强和结构化循证安全报告
- `/medical-agent`：安全分诊、证据检索、临床安全复核三阶段 Agent
- `/knowledge-base`：医疗文档元数据上传、异步索引和带来源问答
- `/tasks`：医疗工作流进度与人工审核状态

所有 AI 对话内容均按 Markdown 渲染，并在插入页面前使用 DOMPurify 清洗。健康问题只通过 POST 请求体提交，不会出现在 URL 中；流式请求支持主动停止并保留不完整结果。

## 本地开发

```bash
npm install
npm run dev
```

开发服务器默认运行于 `http://localhost:3000`，并将 `/api` 代理到 `http://127.0.0.1:8123`。可复制 `.env.example` 并通过 `VITE_API_BASE_URL` 覆盖 API 地址。

## 构建

```bash
npm run build
```

Nginx 配置包含适用于 POST SSE 的关闭缓冲与长连接设置。

## 用户与数据库会话

访问应用时先检查 `GET /api/auth/me`，未登录进入 `/login` 输入用户名和密码，通过 `POST /api/auth/login` 登录。后端初始化账号为 `zhangsan`，密码为 `123456`，需要手动输入，不自动登录。登录成功后返回原页面；点击“退出登录”调用 `POST /api/auth/logout` 使服务端 Session 失效。前端不保存密码或认证 Token；Axios 与 SSE 请求均携带会话 Cookie。跨域部署需要后端允许携带凭据，并满足浏览器 Cookie 策略。

新建对话先调用 `POST /api/ai/sessions`，成功后再显示和使用服务端返回的会话 ID。普通问答与安全报告共用 `medical` 历史，循证检索使用 `rag` 历史，深度分析使用 `agent` 历史；历史查询及删除使用相同类型。创建会话要求后端启用 MySQL 持久化模式。

历史消息恢复正文、报告、Agent 调用路径和运行状态；生成中、失败、已停止的空回复也会展示。历史消息仍在生成时可点击“刷新状态”读取最新结果。RAG 历史当前仅由后端保存回答正文，历史引用来源不会自动恢复。任务页按当前用户查询任务，提交时由后端确定任务归属。

运行 `npm test` 检查历史解析和会话创建、切换、停止的行为，运行 `npm run build` 验证生产构建。

## 医疗安全约束

- 任意页面持续展示“不能替代专业诊疗与急救”的安全边界。
- 回复包含“拨打 120”或报告风险级别为 `EMERGENCY` 时，显示不可关闭的红色紧急提示。
- 循证来源展示发布机构、版本、发布日期、适用人群、生效状态和审核状态。
- 未检索到来源时明确提示证据不足，不把回答包装成确定的医疗结论。
- 输入区提醒用户不要提交无关的身份信息。
