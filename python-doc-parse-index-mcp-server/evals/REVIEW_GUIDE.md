# 候选问题人工审核规程

审核对象是 `candidate_review.csv`。原始 Ragas 输出保留在 `candidates.jsonl`，不要在
原始文件上覆盖，以便追查生成偏差。

新生成流程把生产父节点及其可追踪叶子组成的“受控证据包”交给 Ragas，再通过证据包正文
精确回连稳定的叶子 chunk ID，不再用全库模糊字符匹配猜测证据。生成输入按文档
round-robin 采样，减少长文档垄断。`generation_warnings` 非空的记录必须重点复核；无法
回连、表格单位不完整或存在重复文本歧义的记录不能直接批准。

每条候选按以下顺序检查：

1. **证据**：`evidence_preview` 是否直接支持参考答案；候选证据只从生产向量索引使用的
   最小叶子 chunk 中匹配。回到 SQLite chunk 或解析后的
   Markdown 核对上下文、表头、单位、页码和否定词。删除仅主题相关但不构成答案依据
   的 chunk ID；需要时补入遗漏的证据 ID。
2. **问题**：问题是否自然、无歧义、无需外部知识，且答案可由已选证据唯一确定。
   避免“该方法”“这项研究”之类脱离上下文就无法识别对象的指代。
3. **参考答案**：数字、单位、实体、比较方向和限定范围必须与证据一致。允许人工改写，
   但不能加入证据中不存在的信息。
4. **泄漏与重复**：问题不能直接泄漏答案；近义重复题只保留信息需求更清晰的一条。
5. **难度覆盖**：最终集合应覆盖事实、解释、比较、跨文档/多跳和中英文查询，不要让
   单一文档或单一题型占据大多数。

审核列的合法用法：

- 接受：`review_status=approved`，并将 `question_verified`、`evidence_verified` 都设为
  `true`。
- 拒绝：`review_status=rejected`，在 `reviewer_notes` 写明原因。
- 待复核：保留 `pending`；它不会进入金标集。

`review_questions.py` 会拒绝未知、空证据 ID，以及没有同时通过问题/证据核验的
`approved` 行。生成者和审核者最好不是同一个人；若只能单人审核，应至少隔一轮会话
复查高难度与多跳样本。
